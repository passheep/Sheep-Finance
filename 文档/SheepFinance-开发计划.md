## 1. 基线与状态口径

当前源码的业务基线是 10 笔费用、整单 30 图、每笔主图与附图合计 10 图、仅主图识别、动态多页 A4、ExcelJS/DOM 导出和 SQLite v3。本计划维护后续验收和发布条件，不保留早期“5 笔、固定单页、Pinia/Konva、Rust Excel 输出”的待办。

“源码已有入口”不等于“本轮已验证”。模块化实施状态、命令输出和详细证据只记录在[代码重构计划](SheepFinance-代码重构计划.md)。旧的前端/Rust 检查及 0.1.x 安装包不计为当前 0.3.0 的验证或发布产物，54 个 Rust 测试也只是源码数量。

| 项目 | 当前限制 |
| --- | --- |
| 前端模块化 | 按本轮职责实施，是否完成及行为一致性证据以代码重构计划为准 |
| 浏览器回归 | baseline/compare 使用独立 Chrome/CDP，不代替桌面 SQL、图片池或备份验收 |
| 桌面存储 | 本轮未验证备份恢复/轮换、迁移一致性；不在正式数据目录试验 |
| 真实 API | 阿里云两种 OCR、OpenAI 兼容大模型未完成本轮真实联调，不承诺准确率或耗时 |
| 导出与环境 | WPS、干净 Win10、安装升级本轮未验证 |
| 凭据保护 | 当前 JSON/DB/ZIP 含凭据，未实现 DPAPI；TXT 不是用户密码加密 |

## 2. 执行约束

- 保持产品版本 0.3.0（软件显示名【报销单助手】，存储标识 `com.sheepfinance.app` 不变）；目录整理不改变 SQL 模型、存储键、27 commands、3 events 或备份格式。后续授权的审批栏选项新增单据 JSON 可选字段，不引入数据库迁移。
- 不新增依赖、Pinia、Router 或测试框架，不修改 `package.json`。Rust 原有域已分，本轮必要性评估不要求重构 Rust。
- `App.vue` 保持组合入口，`types/constants/utils/services/composables/features/export/styles` 按职责组织；`useSheepFinanceApp` 组合 12 模块，各 view typed `provide/inject` 复用同一 root state，草稿/设置各有唯一所有者。
- 恢复费用仍限前 10 笔，但历史附图不套用新增图片的完整 10/30 图截断；不以“容量规范化”为由丢图。
- 原图先行、SQL 引用事务、识别前保存、人工字段保护、保存修订和恢复门禁均保持原语义。
- 按改动目标做最窄验证，不把全仓构建、全量 `cargo test` 或每阶段 Tauri 打包列为门槛。
- 正式目录不测试；本轮不启动 Tauri、不触发备份/恢复/轮换或永久删除测试。桌面写入须先准备一致性隔离副本，并确认 runtime 指向该副本。
- 不在文档、样本或日志证据中放真实凭据和真实报销数据；不自动提交或推送。

## 3. 后续阶段与完成条件

以下均为验收要求，不是已完成勾选项。

| 阶段 | 目标 | 完成条件 |
| --- | --- | --- |
| A 前端职责归位 | 展示、业务组合、typed API、导出和样式分离 | 12 模块职责清晰；主控状态不复制；原 DOM、事件、CSS 顺序与引用保持兼容；细节记入代码重构计划 |
| B 前端行为一致性验证 | 用已有工具证明业务与导出未回归 | 对应纯函数、view、业务、类型和保留产物构建检查有本轮证据；旧提交 baseline 与新代码 compare 的隔离浏览器回归通过 |
| C 桌面数据验收 | 确认持久化、迁移与恢复语义 | 在一致性隔离副本中完成 SQLite/图片、迁移失败门禁、恢复及快照轮换检查；不写正式目录 |
| D 真实识别验收 | 两种 OCR 和模型提取形成闭环 | 经授权用脱敏样本和受控配置完成成功/失败路径；人工字段、迟到响应及 OCR 保留规则正确，记录实际耗时而非预设承诺 |
| E 发布候选验收 | WPS、打印和 Windows 安装升级 | 经授权审查构建/产物策略后生成实际当前版本包，完成干净 Win10 和 WPS 验收，记录版本、哈希、环境及结果 |

凭据安全升级需另行确定范围；当前固定内置 secret 的配置 TXT 不能替代 DPAPI。发布前必须明确披露现有存储风险，不能把尚未实现的保护列为已完成能力。

## 4. 验证入口与选择

命令、前置条件和目录职责统一维护在 [app/README.md](../app/README.md)，不在这里复制执行日志。使用 `app/` 下已装工具：

| 入口 | 适用范围 | 限制 |
| --- | --- | --- |
| `node --test src/__tests__/pure.test.mjs` | 金额、分页、类型/常量与旧提交比较 | 不证明桌面持久化或真实 API |
| `node --test src/__tests__/views.test.mjs` | 原 DOM/事件表达式、CSS 字节顺序、DOM refs | 不代替浏览器和打印实测 |
| `node node_modules/vue-tsc/bin/vue-tsc.js --noEmit -p tsconfig.json` | 前端类型契约 | 不写生成产物，不代表业务通过 |
| `node --test src/__tests__/business.test.mjs` | 保存与识别的门禁、版本、恢复及迟到结果 | 内存存储与 mock 服务，不访问真实 API 或桌面目录 |
| `node --test src/__tests__/preview-editing.test.mjs` | 审批默认/保存、100 步预览字段历史及快捷键边界 | 内存存储，无桌面 IO；历史不跨重启 |
| `src/__tests__/refactor.browser.test.mjs` 的 baseline/compare/features | 独立 Chrome/CDP/Vite/localStorage 中的工作台、真实交互和导出 | 原重构 compare 需旧版基线；新功能使用独立预期的 features，不覆盖旧截图；浏览器不等于桌面存储 |
| Vite `build({build:{emptyOutDir:false}})` | 改动前端的产物构建 | 需独立类型检查，保留已有产物，不用默认清空方案替代 |

前端构建入口：

```bash
node --input-type=module -e 'import {build} from "vite"; await build({build:{emptyOutDir:false}})'
```

Rust 若未来有实际改动，只验证相关目标并先审查其写入/清理行为；未经审查的全量测试、Tauri 启动不作为本轮门禁。Vite 配置已保留旧产物；安装包构建已经授权，重建前另存同名旧包，安装/升级验收仍属于阶段 E，不能由打包成功替代。

## 5. 风险与验收重点

| 范围 | 必须覆盖的检查 |
| --- | --- |
| 容量与恢复 | 第 11 笔、第 31 图、单笔第 11 图被新增入口限制；历史费用前 10 笔恢复及其全部既有附图保留，容量耗尽后不追加 |
| 金额与字段 | 表达式/负数/小数转整数分、非法输入与除零、人工总额覆盖及恢复自动合计；新建公司/报销日期为空，资料快照不回写 |
| A4 分页 | `794 × 1123`、动态行高首/续预算 `785/816`；每组 6 图，`single` 仅一页表格且余量 `>=126` 合第一组，`double` 独立，均覆盖超过两页 |
| 识别并发 | 只有主图识别；保存失败不发请求；删除、切单、重复识别后的 ID/`recognitionVersion` 检查；`manualFields` 保护及模型失败保留 OCR |
| 审批与编辑历史 | 财务/秘书处及总经理显示选择随单保存，旧数据默认兼容，Excel/PDF/打印不导出控件；输入提交、撤销/重做分支、100 步、切单清栈、临时导出保栈及焦点边界 |
| 保存与共享状态 | `900ms` 防抖、revision 与 loading/storageReady/suppress 门禁；view 和 DOM refs 使用同一状态，历史临时导出不写回草稿 |
| 历史与演示 | `createdAt + ID` 稳定倒序；日期筛选取第一笔费用日期；浏览器历史前 20 项不被误当作桌面数据保证 |
| 局域网 | 15 分钟到期、目标费用和剩余容量同步、目标删除与切单后失效，迟到上传不进入其他单据 |
| SQLite 与原图 | v3/11 表、WAL/FK/FULL；records JSON 与费用/附件 SQL 同事务；原图先行且不能 SQL 回滚，哈希、引用及跨单归集兼容 |
| 迁移与恢复 | JSON/`.bak` 回退、corrupt 门禁、设置默认回退需确认、缺失/损坏数据库不静默建空库；72 小时条件调度及最近 5 快照；完整 ZIP 全引用图和哈希清单 |
| 导出与打印 | 当前单据范围、Excel 动态费用/公式/大写文本、图片变换、PDF 页数；WPS 打开/保存/打印与 A4 实测，不能仅凭生成文件宣称兼容 |
| 安全与环境 | 凭据实际存储限制、TXT version 1 固定 secret/AES-256-GCM/PBKDF2-SHA256 180000 次；中文路径、Windows 缩放、安装升级及异常恢复 |

上述桌面、真实 API、WPS 和安装项本轮均未验证。桌面副本必须包含一致性数据库与所有引用图片，不能只复制正在使用 WAL 的 `.db`；涉及恢复、轮换、清理的验证另行审查并授权。

## 6. 0.3.0 发布条件

只有具备对应版本的实际证据后，才可标记发布候选完成：

1. 字段映射与空栏语义得到确认，10 笔/30 图、历史附图、负数/人工总额及多页业务无阻塞性回归。
2. 对改动目标的类型、纯函数、view、业务、保留产物构建与隔离浏览器检查通过；compare 未完成时保持该项未验证。
3. 在隔离数据中证明单据与原图能重启恢复、迁移一致、损坏门禁有效、快照恢复/轮换和完整 ZIP 导入导出可靠。
4. 阿里云 `advanced/handwriting` 和至少一个 OpenAI 兼容模型完成受控真实调用，识别失败仍能手工继续且保留原图/OCR。
5. WPS 验证 Excel 打开、再保存和打印，PDF/应用打印按实际页数验收；不承诺未经测试的像素级一致性。
6. 当前版本 NSIS 包在干净 Windows 10 x64 完成安装、启动、升级与卸载，现有数据不因安装升级丢失；旧 0.1.x 包不能替代。
7. 当前 JSON/DB/ZIP 凭据风险、TXT 加密边界及未实现 DPAPI 的事实已披露并完成安全决策；无阻塞级金额错误、图片串单或数据损失。

2026-10-10 已完成审批栏选项、预览字段撤销/重做和统一图标，随后完成软件改名【报销单助手】、顶栏品牌块移除、导航左移和版本 0.3.0。审批选项作为 Draft JSON 可选字段随单据保存，预览、Excel、PDF、打印共享同一默认和呈现规则；历史最多 100 步，切单/重新载入清空，临时历史导出保留原栈。图标使用 `文档/报销申请.png` 生成网页、应用、安装和卸载资源；关于页、窗口标题、任务栏、网页标题、手机上传页和导出默认文件名统一改为【报销单助手】。顶栏不再显示品牌文字和图标，主标签区从左上角开始。
