## 1. 目标与范围

### 1.1 重构目标

- 将 `app/src/App.vue` 中的类型、计算、接口调用、业务状态、页面展示和导出逻辑按职责拆分。
- 明确共享状态的所有者、模块之间的依赖方向和各类副作用的生命周期。
- 保持现有界面、操作流程、识别规则、金额计算、排版、导出和数据兼容。
- 按必要程度整理 Rust 大文件，保留命令入口、事务边界和持久化规则。
- 修订项目说明、开发设计和开发计划，使文档描述与最终实际实现一致。

验收依据是职责清晰、行为兼容和验证证据，不以文件数量或单文件行数作为唯一目标。

### 1.2 允许涉及的范围

| 范围 | 用途 |
| --- | --- |
| `app/src/` | 前端类型、服务、业务逻辑、组件、导出和样式拆分 |
| `app/src-tauri/src/` | 必要的 Rust 内部模块整理及针对性测试 |
| `README.md`、`app/README.md` | 实际功能、运行方式、开发入口和目录职责说明 |
| `文档/SheepFinance-开发设计文档.md` | 最新业务规则、架构、存储和导出设计 |
| `文档/SheepFinance-开发计划.md` | 已实现、已验证和待验证事项整理 |
| 本文 | 阶段状态、实际落点和验收结果更新 |

以上是总边界，不等于一次授权修改其中所有文件。每阶段开始前，必须列出本阶段明确的新增、修改文件及验收项；不得顺手修改无关文件。

### 1.3 本轮不包含的工作

- 新增业务功能、调整业务限制、改变界面设计或优化现有业务行为。
- 更换框架、存储方案、导出方案或识别供应商。
- 为模块化而引入 Pinia、Vue Router、测试框架等新依赖；确有需要时须先说明理由并取得用户确认。
- 改变数据库结构或版本、存储位置、历史数据格式及备份格式。
- 重建正式数据库、清理原图、删除备份、清理旧 JSON 归档。
- 修改应用标识、安装升级策略、权限配置或产品版本号。
- 自动提交、推送、切换分支、重置工作区或清理用户已有文件。

发现疑似缺陷时，记录触发条件与证据，单独确认修复范围，不混入模块搬迁。

## 2. 当前实现基线

本节以编制时的代码为准，旧设计文档中“5 笔费用、单页 A4”等描述不能直接作为重构依据。

### 2.1 架构与代码分布

| 模块 | 当前实现 |
| --- | --- |
| 桌面与前端 | Tauri 2 + Rust；Vue 3 + TypeScript + Element Plus + Vite |
| 应用与状态 | `App.vue` 约一万行，使用 Vue Composition API，集中处理业务与页面 |
| 图片展示 | `components/AttachmentSurface.vue`；使用 DOM/CSS 变换进行取景、旋转和定位 |
| Excel | 前端 ExcelJS 生成可编辑表格，附件区域使用截图 |
| PDF | 前端 html2canvas 捕获纸页，jsPDF 按页生成 PDF |
| 数据层 | `storage_sql.rs` 命令入口，`database.rs` 实现存储、查询与迁移 |
| 附件 | `attachments.rs`，原图按 SHA-256 存储并按单据归集 |
| 备份 | `backup.rs`，数据库快照与完整 ZIP 导入导出 |
| 识别 | `recognition.rs`，阿里云 OCR 与 OpenAI 兼容大模型接口 |
| 手机上传与日志 | `lan_upload.rs`、`request_log.rs` |

代码虽然依赖 Konva，但当前附件展示采用 DOM/CSS；重构不得按照旧设计将其重新实现为画布编辑器。

### 2.2 必须保留的业务行为

| 项目 | 当前行为及保留要求 |
| --- | --- |
| 数量限制 | 新增入口最多 10 笔费用、整单 30 张图片、每笔含主图最多 10 张图片 |
| 主图与附图 | 导入主图创建费用；附图不增加费用行，仅主图参与 OCR/LLM |
| 稳定关联 | 使用单据、费用、附件 ID 关联，排序不改变身份；主图附件 ID 使用费用 ID |
| 金额 | 持久化为整数分；保留现有表达式解析、负数处理、舍入、手工覆盖和大写转换 |
| 识别 | 保留普通/手写模式、配置选择、OCR 原文、模型结果、错误及耗时 |
| 人工字段 | `manualFields` 保护人工编辑值；未人工确认的事由和安排人按现有逻辑清空 |
| 异步结果 | 保留费用存在性和 `recognitionVersion` 检查，避免迟到结果污染当前数据 |
| 保存时机 | 900ms 防抖；识别前先成功保存；保留加载及临时导出期间的保存抑制 |
| 保存状态 | 保留 `autoSaveRevision` 语义；请求完成不等于期间的新修改已保存 |
| 表格分页 | 保留现有行高估算、首页与续页预算，以及合计等区域的位置 |
| 附件分页 | 按费用顺序展开，主图先于附图，每组最多 6 张 |
| 同页模式 | `single` 仅在表格一页且剩余高度满足条件时合入第一组附件 |
| 独立分页 | `double` 将附件组独立分页；两种模式均可能超过两页 |
| 历史 | 保留公司/状态/列表视图、筛选、分页、详情、继续编辑和复制为新单 |
| 历史排序 | 桌面端按创建时间及 ID 倒序稳定排序，编辑或状态变化不改变创建顺序 |
| 日期筛选 | 保留历史查询使用第一项费用日期的现有语义 |
| 浏览器回退 | 保留 localStorage 存储及最多持久化前 20 条历史的现有行为 |
| 手机上传 | 带短期令牌的局域网会话；保留主图/指定费用附图目标及容量同步 |
| 默认资料 | 新建单据复制资料快照，修改设置不回写历史单据 |

补充说明：新增入口的图片上限，不等于历史恢复入口已经执行相同截断。当前恢复会将费用限制为 10 笔，附图恢复没有相同的完整截断规则；不得借重构新增截断并丢失历史附件。

新建单据的公司、报销日期等字段按当前代码保留空值和人工确认行为，不根据旧文档擅自带入默认值。当前保存也没有“全部字段完成复核”的强制门槛。

## 3. 正式数据与备份保护规范

### 3.1 保护对象

默认正式数据目录为 `%APPDATA%\com.sheepfinance.app`，必须以实际运行时解析的目录为准。保护整个目录，至少包括：

- `sheepfinance.db` 及存在时的 `sheepfinance.db-wal`、`sheepfinance.db-shm`。
- `images/` 下全部原图、识别副本和按单据组织的文件。
- `backups/database/`、`backups/full/` 及用户另存到其他位置的完整 ZIP。
- `legacy-json-*` 旧数据归档、`recovery-preserved-*` 恢复保留文件。
- 已有的恢复、迁移暂存文件及用途尚未确认的用户文件。

禁止将项目目录、临时目录与正式数据目录混淆。禁止为了方便测试移动、覆盖、重命名或删除正式数据及备份。

### 3.2 一致性副本与测试隔离

1. 启动任何桌面验证前，先确认实际数据根目录。当前 `npm run tauri dev` 本身不保证使用独立目录，不能直接视为安全的测试入口。
2. 使用独立测试环境和独立数据目录。执行阶段必须说明具体隔离方式并验证实际路径；当前尚未确认已有测试数据目录开关，不得假定存在。
3. 数据副本应来自停写状态下的一致性复制，或经确认的 SQLite 一致性快照方式。不得把正在写入的主 DB 单文件复制认定为完整备份。
4. 测试图片须复制实际字节，不能与正式原图建立硬链接或符号链接。副本中的图片路径也必须解析到副本内部。
5. 旧版基线程序与重构程序使用两份独立副本，执行相同操作后比较结果。不能让两者轮流写同一份测试数据库。
6. 正式数据副本、真实票据和密钥不得提交 Git；报告采用脱敏摘要，不输出凭据或完整业务资料。
7. 若无法建立并确认隔离环境，停止有写入副作用的验证，只开展源码阅读、静态检查和安全的纯逻辑验证，并如实标明未验证项。

### 3.3 备份轮换的特别限制

现有 `create_database_backup_at_root` 创建快照后会轮换有效备份，保留最近 5 份；启动及后续保存也可能调度备份检查。其 72 小时规则是检查条件，不是一个持续运行的定时器。

因此，重构期间不得在正式目录调用“创建数据库备份”来充当保全操作，不能因创建新快照而删除用户既有备份。若需要新增保全副本，应先确认只新增、不覆盖、不轮换的方式，并保存到独立位置。

备份、恢复、迁移、孤立图片清理、旧归档清理等具有文件副作用的流程，只能在满足删除安全规则的隔离环境中验证。正常业务中的备份策略保持原样，不在本轮顺手调整。

### 3.4 文件删除安全

- 不永久删除任何文件或目录，包括测试产物和源代码文件。
- 需要移除明确普通文件时，只能使用 `recycle_file`，逐项说明用途与影响，由用户统一确认。
- 不使用 `rm`、`git clean`、`git rm` 或编程语言文件删除 API 进行清理。
- 目录或根据搜索结果批量删除须转交用户手动处理；用户取消删除后立即停止该删除任务。
- 现有数据库/备份测试含 `remove_dir_all`、`remove_file` 等调用，轮换与清理业务本身也有删除副作用。执行前必须审查具体用例及调用链，不能直接运行整个测试套件。
- 隔离副本不构成永久删除的授权。含禁止删除行为的用例须暂缓，保留未验证状态；如需调整测试策略，须先明确额外范围，不能默默绕过规则。

## 5. 目标模块结构与依赖规范

### 5.1 前端目标结构

下面是职责目录约定，具体文件随对应阶段建立；不得一次创建全部空目录、空组件或占位实现。

```text
app/src/
├─ App.vue                         # 应用组合入口与页面切换
├─ main.ts                         # 挂载入口
├─ types/                          # 业务模型、接口载荷类型
├─ constants/                      # 业务限制、存储键、页面尺寸
├─ utils/                          # 无业务状态的金额、日期等计算
├─ services/                       # Tauri 调用、事件、浏览器存储适配
├─ composables/                    # 有明确状态所有者的业务逻辑
├─ features/
│  ├─ workbench/                   # 制单、费用编辑、A4 预览与工具栏
│  ├─ history/                     # 历史查询、列表、详情
│  ├─ settings/                    # 资料、字典、识别配置、备份与配置迁移
│  └─ about/                       # 关于页面
├─ components/
│  ├─ AttachmentSurface.vue        # 保留现有附件展示组件
│  └─ RequestLogsPage.vue          # 请求列表及常驻详情弹窗
├─ export/                         # Excel、PDF、截图及资源准备
└─ styles/                         # 基础、业务、预览和打印样式
```

建议逻辑落点包括 `useWorkspace`、`useSettings`、`useHistory`、`useRequestLogs`、`useRecognition`、`useAttachments`、`useLanUpload`、`usePreview`、`useBackups`。命名和数量在阶段文件清单中确定，不为满足目录结构额外制造模块。

### 5.2 状态与依赖方向

- `types`、`constants` 不依赖页面、业务状态或服务。
- 纯 `utils` 不访问 Vue 实例、DOM、localStorage、Tauri 或网络。
- `services` 封装外部调用，不持有当前草稿，不直接依赖页面组件；错误仍按现有语义向调用方传递。
- 业务模块通过明确参数接收依赖，不从 `App.vue` 导入状态，不形成模块循环引用。
- `useWorkspace` 统一管理草稿身份、载入/替换和保存协调；其他模块使用同一个响应式对象。
- 设置、历史和选中态分别指定唯一所有者。不能在不同模块重复创建草稿、自动保存监听或手机上传监听。
- 展示组件通过 props 和 emit 使用数据与操作；仅在确有跨层共享需要时使用有类型的 provide/inject。
- 导出模块接收单据快照、现有分页结果及所需 DOM/资源，不能自行重新实现一套分页算法。

### 5.3 生命周期、样式与界面保护

- 明确 watcher、计时器、窗口事件、Tauri 监听、对象 URL 的创建者和清理者，各自只注册一次。
- 保留 `nextTick`、保存抑制、编辑提交和资源等待的执行顺序。
- 拆组件时逐一迁移模板依赖，保留焦点、键盘、拖选、滚轮、冒泡和弹窗关闭行为。
- 保留 DOM 层级、尺寸、表格结构、截图定位属性及 `data-export-*` 属性。
- 当前全局样式不能在拆分时全部直接改成 scoped；先保留选择器和加载顺序，再处理必要的归属。
- 打印媒体规则、分页断点、滚动容器、预览缩放和左栏宽度行为必须保留。
- 注释、设计说明和新增测试描述使用中文，解释必要的业务取舍，不复述显而易见的代码。

### 5.4 Rust 内部整理原则

优先完成前端拆分。Rust 阶段仅在范围确定后开展，可按连接与结构、单据保存、历史查询、图片、迁移等职责拆分 `database.rs`。

保留 `storage_sql.rs`、`attachments.rs`、`backup.rs` 等现有外部入口；内部可使用子模块及明确的重导出，避免机械扩大所有函数的可见性。不得改变存储锁、`spawn_blocking`、事务提交、文件写入顺序和错误传播，也不得将事务内步骤拆成多次独立提交。

### 7.3 比较与判定方式

- **数据：** 比较单据/费用/附件数量、稳定 ID、字段值、排序、SQL 与 JSON 一致性、外键及图片引用；对已有备份记录路径、大小和 SHA-256。只读快照可执行 `PRAGMA quick_check`、`PRAGMA foreign_key_check` 核对完整性。
- **操作后的数据：** 两份副本执行同样操作后做语义比较。对时间戳、日志等正常变化单独说明，不得忽略金额、附件或人工标记等业务差异。
- **文件：** 图片原始字节和哈希保持一致。数据库运行后可能因 WAL、日志或保存发生字节变化，不以整个 DB 的二进制完全一致替代语义验证。
- **导出：** 比较页数、表格值与公式、图片数量/顺序/位置及打印设置；Excel/PDF 可能包含生成时间等差异，不以文件哈希相等作为唯一标准。
- **界面：** 使用相同窗口尺寸、缩放、字体和样例截图比较；出现行高、分页或内容缺失差异时必须定位，不能以“重构导致”作为接受理由。
- **环境故障：** 网络、工具链、隔离条件阻挡与代码错误分别报告；不得将未运行或失败检查标记为通过。
